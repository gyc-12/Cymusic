T02 保留 `Documents/mmkv`、`Documents/cache/mmkv` 和原数据库身份。
旧地址解析、歌曲 ID、删除所有权及异步删除时的记录身份检查保持原有规则。
下载先进入唯一临时文件，取得真实 HTTP 200 后才移动到最终地址；失败时清理
临时文件和进度监听。设置页读取文件选择器返回的原始 URI，避免把文件名中的
`#`、`%` 或中文误当成 URI 语法。

下载存在明确差异：Expo 公开接口不提供原 RNFS 的 15 秒请求超时和 1 小时资源超时
设置，并禁用 URLCache；非 200 的其他 2xx 不再留下业务层已经判失败的最终文件；
移动失败会 reject。`File.move({ overwrite: true })` 会先删除旧目标，因此不能承诺
原子替换或所有移动失败都保留旧文件。这里使用的 Expo `/legacy` 下载 API 仍通过
Expo Modules 工作，目录名不代表采用旧 React Native Bridge。

上述备份验证在独立模拟器上完成，未改动原验收主体，也没有用旧 MMKV2 二进制
读取 MMKV4 数据。它验证备份数据库的读取和文件保留，不代表跨模拟器自动重定位、
全部 AsyncStorage、完整 Release 数据比较或真机安装迁移已经通过。

T05 的实际回归中，旧实现让新音源的 1000 毫秒计时器在约 162 毫秒时触发；
新实现的独立 JSC 检查约 1013 毫秒，iOS 检查为 1008 毫秒。取消、重载和销毁
在服务端分别观测到未完成连接于 40、32、34 毫秒关闭。测试后原选中 LX 音源已
通过原 reload owner 恢复，18 个数据库键值保持一致，没有非预期键值变化或清理错误。
原生私有计时器、JSC context 和内部映射的清理计数来自 Foundation/host 检查；
iOS 的回调静默与连接关闭证据不替代这些内部检查。

T04 补齐首次读取与 KVO 注册之间的音量快照，清理卸载后的监听和迟到读取。
T07 将网络超时、短延迟和睡眠截止时间分开管理：请求结束或取消时清理 timer 和
有限 UIKit 后台任务，迟到的任务标识也会释放；睡眠定时只暂停播放，并过滤取消或
替换后的旧事件。调度失败保留原定时任务。`useTimingClose` 的间隔清理已验证，
但该 hook 当前没有活跃页面消费者，不能将其检查表述为页面倒计时显示验收。

iOS 运行还暴露了原有取消错误映射的兼容缺口：Expo fetch 的原生取消异常不再
使用字面值 `Aborted`。两个请求 owner 现在依据自身 AbortController 的取消状态
归一为原有错误，再交给既有公共接口映射；没有取消的普通错误保留原对象。
修正后，600 毫秒超时在服务端观测到 626 毫秒关闭连接，手动取消在 30 毫秒关闭；
两者继续使用原公共接口的「请求超时」提示。迟到的真实原生睡眠事件未触发暂停，
替换后的当前截止时间只触发一次。此检查使用空原生队列验证到 RNTP.pause 的调用路径，
不代表可听播放、后台或真机通过；同值音量设置成功也不代表物理音量变化。

原始文件字节比较限定在停机覆盖安装前后；正常启动会产生 MMKV 追加写入，
运行前后用完整逻辑键值比较。已记录的 T05 启动/运行之后，两份数据库的 18 个值
保持一致，原始文件字节并非全部不变。

播放器保留的原因是实际能力差距：Expo Audio 57.0.4 有原生 playlist，但锁屏 owner
只接收 AudioPlayer，缺少当前需要的上一首/下一首指令入口。Audio API 0.13.3 提供
这些原生指令，但仍需根播放器生命周期、动态音源解析和状态/进度/歌曲身份适配，
不能只替换包名。RNTP v5 的许可不满足本轮选择，未引入。详见
[播放器审计](../audit/2026-09-09/audio-analysis.md)。这些结论来自精确版本的源码与
公开 API 比较，候选引擎未安装进应用，也未进行候选原生运行验收。

Expo Sharing 57.0.18 使用新的 UserDefaults key、载荷结构及扩展 target 生成规则。
它不能直接读取旧 `cymusicShareKey`、历史 plist/JSON 载荷和 `#clip` 通道，也不能
直接接管当前 `ShareExtension`。移除旧库前需要双读兼容、明确的 target 接管、
冷启动/热启动和重复分享验证。本轮保留原 writer、reader、App Group 与补丁。
