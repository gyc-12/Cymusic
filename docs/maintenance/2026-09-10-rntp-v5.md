# RNTP v5 集成记录

本次从 `2f1d0ec122ce255435483b065da505d7dbedf7b5` 迁移播放器，固定使用
`@rntp/player@5.9.2`。Expo 57.0.21、React Native 0.86.3、React 19.2.3、
iOS 16.4+ 及现有原生工程保持一致。本轮代码、依赖锁、补丁、回归检查和说明
作为一个提交交付；未纳入个人工具配置或原有 IDE 文件删除。

## 集成范围

- 移除 `react-native-track-player@4.1.2`，原生 Pod 改为 `RNTPPlayer (5.9.2)`，
  移除旧播放器及其 `SwiftAudioEx`。采用 v5 的 New Architecture 原生接口。
- 原业务队列、音源解析、音质回退、缓存/下载、导入音乐、歌词、系统音量和睡眠
  截止时间继续由原来的应用模块负责；不另外启用 v5 缓存、预加载或睡眠计时器。
- 应用自己的 `Track` 类型保留 `id/platform/artwork/album/url`。在播放器边界
  转为 v5 `MediaItem`，包含明确的媒体 ID、封面/专辑字段和 HTTP headers。
  原生 getter 会省略 headers、可能返回本地原始路径，不能用于重建待播音源。
- 原生队列仍为当前曲和静音占位项。每次替换生成新 token；自动切歌验证当前
  媒体、token、占位位置和播放意图，忽略过期、重复和清空事件。单曲循环每轮
  重新装载保留的完整音源，原生 repeat/shuffle 关闭，由业务队列选择下一曲。
- v5 命令返回 `void`，getter 同步返回。进度 hook 参数改为秒；UI 分别读取
  playback state 和实际 `isPlaying`，不再把 Ready 当成正在播放。
  原生中断暂停后，删除当前曲不会自动启动下一首。切歌后的界面刷新读取当前
  原生快照，进度条和拖动目标不沿用上一曲的轮询时长。
- 切歌请求、迟到音源和错误恢复遵守选择/操作代次。暂停期间完成的当前音源
  保持暂停；停止期间完成的音源保持停止。旧请求不能替换新选择或释放新切歌锁。
- MMKV/AsyncStorage 的名称、键、目录和序列化结构没有迁移。App、分享扩展、
  App Group 及现有分享协议保持原样。v5 本地进度同步会维护其原生 saved-progress
  preference；这不是应用曲库的另一个持久化实现。

## 固定补丁

[`@rntp+player+5.9.2.patch`](../../patches/@rntp+player+5.9.2.patch) 包含两处
适配，仍由严格的 `patch-package --error-on-fail` 应用：

1. iOS hybrid 遥控：上游原生执行 Play/Pause/Stop 后没有通知 JS，迟到的音源
   可能覆盖系统暂停。补丁在现有 handler 中先确定动作，再执行一次原生命令并
   发出一次对应事件。应用只更新意图；Next/Previous 由业务队列处理，Seek 保持
   原生处理。没有增加第二套音频引擎或重复执行同一遥控命令。
2. 删除 `trackPlayerModule.ts` 中针对旧 React Native 类型的失效
   `@ts-expect-error`，避免 RN 0.86 下产生新增 TS2578；不改变运行逻辑。

## 验收边界

模拟器工具两次在点击播放器入口时返回 `windowNotFoundAtPosition`，包括聚焦窗口
后的重试。因此未完成本轮播放器展开、实际按钮点击、滑块拖动和下拉关闭的整组
手势检查；探针超时后完成数据恢复，不能将它计为通过。播放/定位接口及 slider
计算已有独立验证，但不能替代一次真实手势验收。

模拟器、未签名构建或本地 handler 回归不能证明真机长期后台、物理耳机/锁屏
命令投递、系统输出音量或有正式 entitlement 的 App Group 访问。没有修改
App 身份、签名配置或清除用户数据来完成验收。这里记录本地验证结果；推送后的
GitHub Actions 须以本次迁移提交为输入单独核验，不沿用旧运行结果。
本轮没有发布签名 App 或 Release。

## 撤回

在包含本次迁移的分支上，对这个完整迁移提交执行：

```bash
git revert <RNTP-v5-迁移提交哈希>
yarn install --frozen-lockfile --non-interactive
cd ios
pod _1.16.2_ install --deployment
cd ..
```

随后按 [README 构建说明](../../README.md#开发指南) 重新构建回退版本，并让原生
二进制与其对应 JS 使用同一个依赖图。切回 Debug 时若复用已有 Pods，请遵循
README 的配置恢复条件。不要让旧 RNTP 二进制连接本轮 v5 的 Metro。

本次回退只撤销播放器迁移，仍保留基线中的 Expo 57 / RN 0.86 / MMKV 4。
没有新的应用数据格式需要降级；回退不要求卸载 App 或删除曲库。保留原有备份，
源码回退本身不会恢复被后续用户操作修改的数据。
